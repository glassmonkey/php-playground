# PHPantom production UI #434 — independent browser check

## Target and method

This run evaluated the integrated UI/Worker on #434 head `297eb093dab237fa378fa954f506378ea70e790c`, not the prototype at port 7260. The manager read back the branch/worktree/clean head, server PID 45416 on `127.0.0.1:8705`, and Docker WASM SHA-256 `2ba179568c31958b731d3eb70f69b788187fcb605094b39d289c4d4caa3ba3da` (18,530,827 bytes). A fresh isolated agent-browser 0.39.1 session used HeadlessChrome 147.0.0.0. The page Worker initialized PHPantom `0.11.1+php-version-setting.3`; selected versions were checked in both `initializationOptions.phpVersion` and `serverInfo.version`.

The served WASM URL was also fetched directly from the page origin; it returned HTTP 200, 18,530,827 bytes, and the manager hash. The Worker resource and version marker were observed in the page. The browser HAR does not expose the internal Worker WASM response body, so the direct fetch is not described as an independent hash of the bytes instantiated by that Worker. See [asset observation](evidence/2026-10-27/browser-observations.json).

For natural completion, each version used the same candidate-free fixture `<?php\n$x = `, typed `strr` with keyboard events, and checked the final two-line model, model version/cursor, matching completion request/response ID, raw item list, and visible Monaco rows. No Ctrl+Space was used. One initial prefix loop produced literal `\n` text; its wrong one-line document/cursor and results were excluded. The affected 7.4 negative probes were repeated with a real newline and matching request positions.
