## Interpretation and limits

**Observed for this head and these tested functions:** selecting 7.4 reached the server (`initializationOptions.phpVersion` and `serverInfo` both end in `php7.4`); after user-visible resolve of `strlen` and `array_fill`, subsequent 7.4 completion did not leak the tested PHP 8.0+ `str_contains` or 8.5 `array_first`/`array_last`, nor 8.4 `array_find`/`array_find_key`. Under 8.5 those candidates were returned and shown. This is a focused pass for the cache-filter regression scenario, not proof that every versioned builtin/stub is gated correctly.

The 7.4 `array_l` server response was `null`, not a completion list with zero items. This is a completed matching response and the UI had no rows, but the result shape differs from a positive list and is reported as such. The temporary Worker response clone perturbed startup; timing was not measured. No parser acceptance or diagnostics behavior was tested here; known parser-version/diagnostics limitations remain covered by the prior report [browser-2026-10-27-new-build.md](browser-2026-10-27-new-build.md). No product source, served asset, or browser profile was changed. CI was not run by this evaluator.

The earlier failure report [browser-2026-10-27-head-91639.md](browser-2026-10-27-head-91639.md) and prior asset-unknown run remain historical evidence and are not overwritten. This retest does not make the product adoption decision.

## Reproduction

In a new isolated agent-browser session on the same fixed asset, enable Completion, use the UI version picker, and confirm the fresh Worker `initialize` response and `serverInfo` each time. With `<?php\n$x = ` and no target names in the document, naturally type `strl` and select/resolve `strlen`; reset the fixture and naturally type `array_f`, select/resolve `array_fill`. Then naturally type `str_c`, `array_f`, and `array_l`, recording each final `didChange`, request/response ID, raw labels/result, and visible rows. Repeat the same warm-up and prefixes at 8.5, then switch to 7.4, confirm the fresh initialization, repeat the warm-up, and test the three prefixes again. Treat missing requests or uncorrelated rows as inconclusive, and preserve `result:null` as distinct from `items:[]`.
